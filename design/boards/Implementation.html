Implementation notes

Accessibility decisions, and how each screen lands in the templates

Everything on this canvas is Jinja plus one stylesheet plus a small vanilla script. Nothing needs a build step, a framework, or a request to the internet. The first day delivers every single-label and batch screen; the review-queue decisions and the export dialog are the second day because they need two small endpoints.

Accessibility decisions (WCAG 2.1 AA, USWDS practice)

  • Colour is never the only signal. Every tag carries a fixed glyph and the verdict word; pins are numbered; banners have a headline; the diff marks a word with bold, colour and a wavy underline.
  • Contrast. Every text/background pair on the Tokens board is at or above 4.5:1 (lowest: pass on its tint, 5.6:1); input borders 4.6:1; the one focus ring is 3 px action blue, 2 px offset, never removed.
  • Real controls. Pins, filters, decisions, tabs and samples are <button>; the drop zone is a <label> around the real <input type=file>; the sample gallery sets a visually hidden <select>, which is also the no-JS path. The single-label form posts to /verify without JS and renders the same partial.
  • Keyboard. Rows are tabindex="0" as today; J/K/arrows move a roving focus, Enter opens, Esc returns focus to the row it came from. Single-letter shortcuts are ignored while focus is in a text field, select or dialog. Drawer and dialog trap focus and restore it to the opener on close.
  • Announcements. The result card is role="status", so the banner headline and summary are read once when a result lands; the reading state sets aria-busy. Batch progress is aria-live="polite" but its text changes only every 25 labels, not every poll. Errors are role="alert". Filters use aria-pressed, pins aria-expanded, icon buttons aria-label.
  • Tables stay tables. Under 640 px rows become stacked cards with CSS, but tr/td keep role="row"/role="cell" so screen readers keep the structure, and each cell is prefixed with its header via data-th as the current stylesheet already does.
  • Images. The label image's alt text names the pinned regions and which one is the problem; crops have their own alt with the text read; highlight overlays are aria-hidden.
  • Motion. One easing, three durations, all set to 0 ms under prefers-reduced-motion; the scanning line and skeleton shimmer are removed, not just stopped. Nothing moves that is not responding to the agent.
  • Zoom and size. Root 17 px; layouts are flex-wrap and auto-fit grids, so 125% and 200% zoom reflow without horizontal scroll; hit targets are 44 px (36 px only inside 40 px table rows, with the whole row clickable).
  • Offline. Public Sans woff2 bundled under /static/fonts with system fallbacks; icons inline SVG; no third-party request of any kind. Print uses @media print in the same stylesheet.

  .ident, header, nav, footer, .btn, .pin, details, #help, #detail, .bulk { display: none !important; }
  body { background: #fff; font-size: 11pt; color: #000; }
  .result { border: 0; box-shadow: none; }
  .split { display: grid; grid-template-columns: 236px 1fr; gap: 16px; }
  .hl { border-width: 1.5pt; } .hl.fail { border-width: 2.5pt; }
  .chip, .banner, tr.bad td { -webkit-print-color-adjust: exact; print-color-adjust: exact; }
  tr, .warning-box { break-inside: avoid; }
  .report-footer { display: flex; } /* reviewer decision, signature, page number */
  @page { size: letter; margin: 0.5in; }
}

"Print report" calls window.print() on the same page; the report footer (reviewer decision, notes, page number) is in the partial but hidden on screen. Tags keep their glyphs so a black-and-white printout still reads.

Naming and attribution (from the legal check)

  • No agency branding. Treasury and bureau names, initials, seals or look-alikes may not be used as branding on an unaffiliated product (31 U.S.C. § 333; disclaimers do not cure it). The canvas therefore shows "Label Check" with a neutral mark; base.html should drop the "TTB" seal and the "· TTB" page title, and the footer should not name a division.
  • Descriptive references are fine. Citing 27 CFR parts 4, 5, 7 and 16, using the regulatory term COLA, and a README sentence saying the prototype models the kind of label review TTB examiners do are factual statements, not branding.
  • Repo and URL. Consider renaming ttb-label-verifier to label-check or cola-label-check before sharing it widely.
