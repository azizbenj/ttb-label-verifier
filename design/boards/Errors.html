Error states

Every way it can go wrong, and what the agent sees

Errors are inline, never pop-ups. They sit where the result would have been, say what happened in one line, say what to do in the next, and keep what the agent already typed. Every one is a role="alert" so it is read out at once. The copy is the current app's copy, tightened.

Behaviour. With JS, the form validates on submit before sending: the summary alert lists each missing field as a link that focuses it, and the first invalid field gets focus. Without JS the server returns the same alert in the result slot and the typed values are echoed back into the form. Nothing the agent typed is ever lost.

No verdict. Only 3 words were read, with 41% confidence, so nothing could be compared. This is not a FAIL.

1.2 sreading 1.2 s

What usually fixes it
  • Use the artwork file or a flat, straight-on scan instead of a photo.
  • Make sure the label fills most of the image and the text is at least 1,600 px wide.
  • Avoid glare, shadows and busy backgrounds behind the text.

Why a separate state. Today an unreadable photo comes back as NOT FOUND on every field plus a warning FAIL, which reads as "the label is wrong" when the truth is "we could not see it". The pipeline already knows: mean OCR confidence and word count. Below a floor (fewer than 8 words or mean confidence under 50%) render this grey, verdict-free card instead of a FAIL, and in a batch mark the row ERROR "Unreadable image", never FAIL.
